# 更新需求 v2

## 1、现状明确

首先恭喜，大部分功能均已实现，框架可运行，但为了能真实使用，我现在做如下功能调整。

## 2、更新需求

### 1、登录

鉴于我个人并不能拿到QQ和微信的登录接口，因此我计划取消所有平台的扫码登录功能。同时由于企业微信和钉钉、Tim等企业用办公交流软件的权限、加密更加复杂，我取消企业微信的登录功能，仅保留微信、QQ两个平台的登录功能。且如果需要账号多开，就请用户自行准备多开工具，我们不管这个了。

### 2、信息获取

目前，微信大部分聊天信息的提取已经实现，但仍有一些问题，需要更新解决：

1. 聊天内容中的文件和推文、链接内部信息需要被读取，重点在于标题和文件中涉及到任务信息（包括名称、主题、时间等），也要以任务的形式呈示。
2. 需要在缩略模式下显示任务的接头人、负责人（分开两行写），以及起止时间。如果这些没有被明确，也应该在缩略状态下告知用户没有明确信息，统一文案为：
   - 接头人：`未明确`
   - 负责人：`未明确`
   - 时间：`未明确起止时间`
3. QQ聊天信息的获取看下使用这个GitHub仓库的内容：`https://github.com/yfgug/QQFlow`，提取后的操作流程与这一版的微信相同。

**边界补充：**

- 文件读取范围：仅读取常见文档类型（`.docx`、`.pdf`、`.xlsx`、`.txt`、`.md`），图片暂不做 OCR，但保留文件引用供用户手动查看。
- 链接读取：只抓取页面标题和正文前 500 字，用于判断是否包含任务信息。若无法抓取，保留原始链接不生成任务。
- 任务生成条件：**只有从文件或链接中提取到至少一个任务关键字段（名称/时间/材料/负责人/接头人）时，才生成任务；否则只在原文中保留该文件或链接的引用，不单独成任务。**

### 3、UI更改

鉴于有时候用户可能会由于错误的使用方式导致一些不是任务的东西被添加进来，需要有一个“多选清除”的按钮，来批量清除任务列表中的所有任务，以待重新添加。

该按钮仅清除所在标签页的所有任务，不清除其他的，更不能清除登录的账户信息和API Key等。一键清除使用与任务中“删除”相同的红色，确认持续时间为2.5秒。普通的“删除”和“完成”的确认持续时间改为1.5秒。

同时为用户提供全选、全不选、反选等现代多选系统应有的功能。在多选模式下，任务左上角或右下角应有复选框，选中的任务在复选框中有对勾以提示已被选中（多选的功能和样式参考主流手机系统相册的多选模式）。

**边界补充：**

- “已删除”标签页的一键清除：确认时间延长到3秒，并在清除前弹窗二次确认，防止误操作导致任务永久丢失。
- 多选模式下，顶部工具栏显示“已选中 X 项”及操作按钮（全选/反选/清除），底部显示“取消多选”按钮。

### 4、新增分类标签

用户大多数时候删除任务的原因是该任务不属于用户的工作范围，或者本身可以选做，而用户不想做，因此新增一个“已删除”分类标签，用来存放。

该分类中的任务可以手动选择恢复。新做一个按钮，原本“完成”和“删除”按钮的区域合并，成为一个大的“恢复”按钮，无需确认，点击即生效。并在页面上方中部弹出绿色提示框提示已恢复，持续时间2秒，有倒数进度条（跟按钮确认的条一样，不过反过来而已），且用户可以点击提示框内右上角的小叉关闭提示框。

**边界补充：**

- “删除”按钮 = 移入“已删除”分类，而非彻底删除。
- 如需彻底删除，在“已删除”分类中长按某个任务，弹出二次确认后再彻底删除。
- 从“已删除”恢复的任务，根据其起止时间和当前时间（UTC+8），自动归入“未开始”、“进行中”或“已过期”，不直接扔回“进行中”。
- 提示框不阻塞其他操作，用户可以继续操作界面。多个提示框同时出现时，队列显示，最多同时堆叠3个，超出部分等待。

### 5、任务自动对比逻辑

新捕获的任务，需要与当前记录的所有分类中的任务进行比对，如有相同的则不再新增（因为我发现有些任务我确认完成后，它按设计从“进行中”移入“已完成”，但同步后又重新进入“进行中”，同时“已完成”中相同的这个任务也没有消失），这点需要改一下。

**边界补充：**

- “相同”判定规则：任务名称 + 发布人 + 起始时间，三者一致即视为相同；若名称有细微差异但发布时间和发布人一致，由 LLM 判断是否为同一任务。
- 比对范围：进行中、未开始、已完成、已过期、已删除，所有分类都要查。
- 若同一任务在多个分类中出现，保留最早创建的那条，其余自动合并发布人信息并删除。

## 3、注意实现

1. UI设计风格定型，不再改变，所有操作应该流畅，支持现代高分辨率，优化到位，感官优雅（参考README.md中的要求）。
2. 所有外部调用（`wechat_exp`、`QQFlow`、LLM API）必须有超时和异常处理，失败时在日志中记录，并在 UI 中给出明确提示。
3. 所有涉及用户隐私的操作，必须在 UI 中明确提示用户。
4. 提供模拟数据模式，无需真实微信/QQ环境即可测试 UI 和核心逻辑。
