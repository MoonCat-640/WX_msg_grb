# 第二次更新需求

## 1、现状确认

目前，我们已经完整地实现了最初设计的核心功能，可以正确读取微信和QQ中的信息，大部分任务也都能准确识别、归类。不过，我依然发现了一点点小问题，在这次更新中争取解决。

## 2、更新需求

### 1、用户可以手动添加任务

此举可以推动该软件实现从“微信QQ信息抓取器”到“能够自动抓取微信QQ信息的综合任务面板”。目前，AI任务识别的准确率已经接近预期水平，但用户可能有些自设任务并不出于社交平台中，因此应该赋予用户自己编辑任务的权力，预期目标如下。

#### a. 用户可以手动添加任务

在“抓取任务”按钮旁，设置一个“新增任务”按钮，样式与“抓取任务”按钮相同，点击后可以新建一个任务，并打开任务详情面板以供用户填入信息，可填写的任务信息种类与自动抓取到的相同。对于用户没有填写的关键信息（要显示在缩略中的信息），在新建完成的任务缩略中像原来设计的一样表明信息未明确。如果是名称或主题未填写，则调用AI生成名称、主题。相关信息在填写后自动保存。

#### b. 用户可以自由编辑/修改任务

用户点击任务缩略，进入任务详情面板后，可以自由修改名称、主题、负责人、接头人、起止时间等信息。对于AI抓取到的任务，用户不能修改信息来源。起止时间的修改方式参照现代网站日历的方式。

### 2、提升安全性

QQFlow的文档中提及，它对密钥等信息只做了基础混淆处理，不够安全。我要求将QQFlow进行魔改（毕竟我们已经有了它的源码），让其实现对账号、密钥等敏感信息用与该软件相同的方式进行加密，以保证数据安全，然后考虑将这个修改贡献到Github上它的仓库中。

**补充说明**：此方案已调整。QQFlow 的 README 中未声明 LICENSE，默认保留所有权利，魔改源码并分发存在合规风险。因此本项**改为**：不改 QQFlow 源码，你的软件仅通过命令行调用 `QQFlow.exe`，把它当作外部依赖。README 中注明“需用户自行从 GitHub 下载并安装”。

### 3、可进入Windows10/11系统托盘

无需每次开启都重新运行 `wechat_exp` 和 `QQFlow`，软件可以在系统后台运行，持续捕获任务（该功能可以在设置中调整开始和关闭）。

**注意实现**：微信和 QQ 的密钥提取需要平台处于登录状态，且存在“密钥窗口期”。软件应监听微信/QQ的登录状态，在检测到登录后触发密钥提取，而不是盲目定时轮询。

### 4、重做安装包Setup.exe

安装时可以勾选是否一并安装 `wechat_exp` 和 `QQFlow`，若用户勾选安装则将这两个软件也安装到该软件的安装目录中，最终做成一个离线安装包。

**补充说明**：此方案已调整。`wechat_exp` 和 `QQFlow` 均为第三方开源工具，README 明确“仅供个人学习、研究用途”。你的安装包**不打包、不分发**这两个工具。安装向导中增加“依赖检查”步骤：检测系统中是否已存在这两个工具，若不存在则提示用户“请前往对应 GitHub 仓库下载”，并附上链接，**不代为安装**。

像你说的那样，自动带上吧。

### 6、项目LICENSE管理

我考虑将这个项目作为一个软件产品发布，并贡献到Github中。请你参考互联网上对于LICENSE的管理，以及 `wechat_exp` 和 `QQFlow` 的凭证信息，为这个项目准备一个LICENSE以便发布。

**补充说明**：项目采用 **MIT License**。在 GitHub 仓库根目录放一个 `LICENSE` 文件，内容为标准 MIT 文本。README 里注明“本项目采用 MIT 许可证，第三方依赖（QQFlow、wechat_exp）遵循各自许可证”。
